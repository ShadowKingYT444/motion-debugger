Folio 02Product

One request writes both sides of the entry

  1. 01

    Request

    Your service sends one POST with an idempotency key. Retry it a hundred times and it posts once.

  2. 02

    Entries

    The debit and the credit are written in a single atomic transaction. The sum is checked before commit, so both land or neither does.

  3. 03

    Settled

    Balances update, the entries are sealed with a hash, and a signed transfer.posted webhook reaches your service.

Folio 03API

Idempotent writes, dated versions, SDKs in six languages

  • Safe to retry

    Send an Idempotency-Key on any write. A repeat within 24 hours returns the first response, byte for byte.

  • Versions pinned by date

    Set Ledgerline-Version: 2026-09-01. Upgrades are opt-in, with a diff for every change.

  • Webhooks you can verify

    HMAC-SHA256 signatures, ordered per account, retried with backoff for three days.

  • A sandbox that fails on purpose

    Simulated rails and clocks, plus fault injection for timeouts, holds and reversals.

  • Typed SDKs from one spec

    Node, Python, Go, Java, Ruby and .NET, generated from the same OpenAPI file the docs use.

Folio 04Reliability

No entry is lost when a region goes dark

A write is acknowledged by a quorum before your request returns, so a lost region costs a slower second and never an entry.

99.999%

Ledger write availability, trailing twelve months, measured at the API edge. Illustrative.

Write path
Synchronous quorum across three regions. An entry is acknowledged only after two of three have it on disk.
Failover
Automatic and rehearsed monthly. Recovery point 0, recovery time under 60 seconds.
Retries
Idempotency keys make every write safe to repeat, so a timeout never becomes a double charge.
