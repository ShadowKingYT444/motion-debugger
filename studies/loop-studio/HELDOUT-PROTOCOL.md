# LOOP Studio independent verification preregistration

Written before either candidate application is inspected. The parent owns the common generation brief and frozen source. This reviewer owns verification and evidence; no candidate repairs, app-state injection, forced input, or post-observation weakening of expectations. Source-specific selectors and responsive coordinate mappings may be added after freeze, with their mapping and rationale recorded before execution. Missing required controls count as failures.

## Shared user journeys

The common brief must include a usable kinetic identity studio, name entry, three visibly different styles Pulse/Weave/Orbit, palette and intensity controls, a scrubber, playback with pause/replay, details/export panel, and valid SVG plus motion-configuration JSON exports of the current composition. Both arms receive identical user expectations and evaluator input schedule.

1. Navigate from an empty fresh context, inspect the entrance and activate the advertised editor CTA using ordinary pointer input. The editor and its actual preview must become usable, with no visible error or uncaught exception.
2. Enter the name VECTOR and select Pulse. Set a distinct palette and intensity using the advertised controls. Hold the scrubber with native pointer down, move along normalized track positions 10% → 85% → 15% → 70%, and release. Reverse twice while held. The displayed time/progress, preview's meaningful pose, selected style/name/palette/intensity, and any live readout must correspond to the released position. The pointer must be released; later controls must accept input. A direct scrub may intentionally track the pointer without easing.
3. While a preset/scene transition is moving, choose Weave, then Pulse, then Orbit using unforced input. Inspect the transient visual states, settle, and verify the final selection, labels, timeline and preview all represent Orbit. No stale completion callback may restore Pulse. Preset transitions must not blank the preview, duplicate unrelated content or lose the current user choice.
4. Play, pause during visible progress, wait, then resume. Displayed progress and the relevant preview pose must freeze together while paused, then continue coherently. Replay/reset must return to the documented beginning and remain usable. After another scrub, open the useful details/export panel and download both a valid SVG and motion-configuration JSON. Both must be nonempty, parseable and represent VECTOR plus the final style/palette/intensity rather than a hardcoded initial example. SVG must contain valid geometry/name; JSON must provide meaningful motion configuration. Orbit requires convincing visible spatial depth, materials, lighting and occlusion; inspect actual frames. Pulse and Weave must have visually distinct identities rather than three spinner variations.
5. Repeat ordinary keyboard navigation and activation. Reach the scrubber and change its value with supported arrow keys. Inspect visible focus and labels; advertised dialogs must contain focus, close with Escape and restore focus. Every advertised control/link/download is checked, including view controls and any cancel/reset action.
6. Repeat on desktop 1440×960, mobile 390×844, and reduced-motion desktop. Primary controls and output must remain reachable and readable without horizontal page overflow. Reduced motion must retain editor meaning and successful export; explicit playback may advance meaningfully while decorative motion is suppressed. Disable WebGL and verify the required fallback retains a useful moving or reduced-motion preview and the complete editor/SVG/JSON export journey.

## Evidence and visual review

Record one complete comparable normal-viewport film per arm and condition. Start recording before navigation and retain entrance, editor work, interruptions, export and final state. Use the same browser version/mode, dependency baseline, viewport, renderer, input timing and semantic actions across arms. Coordinates map to the actual rendered track/control, not fixed desktop pixels. Both arms keep ordinary browser tools; only the assisted arm gets the plugin treatment defined by the parent. No image screenshots, locator screenshots or full-page screenshots during film recording.

Calibrate full-viewport coverage using independently recorded corner markers before relying on the films. Retain the raw recording and any transform metadata. Reject clipped/resized coverage rather than silently presenting a cropped film. Full videos preserve original timing; sparse frames do not replace them. Inspect actual desktop/mobile initial and final screenshots in separate nonrecording contexts, then decoded film frames around every reversal and transition, plus the useful export. Frame seek alignment is approximate and its uncertainty is reported.

For pause, use independent lossless native viewport screenshots with offline crop of the preview and progress region. Preserve exact hashes and pixel differences. Byte differences alone do not establish visible motion; report the magnitude and inspect actual pixels. Lossy codec differences never become a failed product freeze assertion without corroborating native evidence. Functional state observations, visual pose observations and recorder cadence are separate results. A script-provided scene counter is supplementary context, never proof of rendered pose or smoothness.

Maintain native input logs, DOM observations, sticky visible-error checks, console/page errors and failed actions. Inspect the actual frame sequence for discontinuities, occlusion, clipping, composition and stale states. Motion assessment must identify the moment and observation supporting it. Insufficient recorder cadence makes smoothness inconclusive; 25fps film cannot establish 60fps performance. Report software rendering and physical-device/browser coverage limits.

## Provenance and decisions

Freeze candidate source/dependencies and exact verification harness snapshots before execution. Hash source manifests, runtime identity, protocol, harness, full recordings, screenshots and exported files. Preserve every failed verifier attempt and classify a verifier bug separately without changing its original recorded status. Corrections create a new attempt, with unchanged candidate source and unchanged user expectations. Record terminal agent status, actual model settings and real elapsed budget from parent provenance.

Report functional delivery, visual review and temporal evidence separately as passed, failed or unverified. A positive functional result does not override a visible defect, and a static/temporally passing target does not establish editor completion. This single paired generation trial supports conclusions about these delivered builds; it cannot establish general coding-agent superiority or isolate the plugin's causal contribution.
