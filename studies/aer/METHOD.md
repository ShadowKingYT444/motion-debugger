# AER paired agent case study

This is one paired demonstration, not a general benchmark or causal estimate.

- Same product brief in PROMPT.md
- Same requested model: gpt-6.1-sol; reasoning effort: high
- Separate agents and isolated source directories, without access to the other arm
- Initial-build allowance:25minutes each; evidence-led repair allowance:20minutes each, excluding mechanical browser-run waiting
- Baseline: ordinary coding/browser evidence, without this project's plugin or new skills
- Treatment: this project's frozen design/3D/workflow skills plus actual Motion Debugger captures and recorded-frame tool responses
- No supplied repair implementation or authored before/fixed switch in either application
- Shared functional/viewport checks and honest reporting of failures

The agents run in a restricted cloud workspace. A coordinator mechanically copies frozen source to a GitHub Actions browser runner and returns requested raw evidence. The coordinator does not supply diagnoses or source fixes to the builder agents. This bridge is an environment accommodation, not a claim that a local plugin was installed in every interactive host.

Model execution is not seeded or token-budget identical. Timing, iteration count, requested evidence and tool availability are recorded. Differences cannot be attributed solely to the skills from one pair. A good baseline must not be intentionally degraded.

Public execution records include prompts, source snapshots/diffs, requested checks, tool outputs, recordings and the agents' concise diagnoses/fixes. They do not contain private chain-of-thought.

AER is a fictional demonstration concept. No external customer system is modified. Repository/public registry publication remains deferred.
