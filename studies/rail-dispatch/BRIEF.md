# SIGNAL / railway dispatch console

Build an original, polished, fully local railway dispatch interface. Motion is the central product, not decoration. Use plain HTML/CSS/JavaScript and inline SVG; no CDN, external media, framework setup or network dependencies. The app must load from index.html under a static server.

Design: premium transport control room; ink navy, warm ivory, electric amber, restrained mono labels, large editorial SIGNAL wordmark. Main visual: expansive original curving railway network with at least three route colors, stations, visibly moving train consists (at least three articulated cars each), pulse/departure signals, and a legible active-train inspector. This must feel like a real designed product, not a generic dashboard. Provide a spacious desktop and intentional 390px mobile composition.

Functional journey: trains run continuously, select Harbor or Summit service, transition network overview to station-focused view and back, change services mid-transition, pause/resume, scrub the timetable (trains must follow it), reset/replay. Curved routes, trains, camera transforms, inspector panels and timeline must stay coherent under interruption and reversal. Reduced motion must retain usable final states and controls. Include a simple export of the current dispatch configuration.

Stable browser hooks, shared across both arms: buttons #harbor, #summit, #overview, #focus, #pause, #replay, #export; input[type=range]#scrub; primary visual #network; selected service text #service-name; expose window.dispatchState() returning {service,view,paused,time}. Use these IDs so identical browser journeys can run. #service-name must include Harbor/Summit. Replay resets time and resumes. Pause button should display Resume when paused. No automatic autoplay sound. Avoid continuous DOM replacement of controls.

Both agents receive the same brief and eight-minute wall-clock budget, inherited model and reasoning settings, and ordinary source/browser tools. Only the assisted agent may use Motion instructions and MCP tools. Each agent owns its own source directory, must not view the other arm, and may not alter the shared brief, viewer or results. This is a small workflow demonstration, not a statistical or blind preference benchmark. Do not deliberately seed a defect in either arm. Source is frozen at the deadline; the parent will record identical visitor journeys without tuning either result.
