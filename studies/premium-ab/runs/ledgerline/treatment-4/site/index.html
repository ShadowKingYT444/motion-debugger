01 Product

One transfer, from request to settled in a single line.

  1. 01

    Request

    Your service calls POST /v1/transfers with an idempotency key. Retry it a hundred times; it lands once.

  2. 02

    Authorize

    Balance, limits and sanctions screening run inline, before a single entry is written.

  3. 03

    Post

    A debit and a credit commit atomically. If they cannot balance, nothing is written.

  4. 04

    Settle

    The payment leaves on an instant rail and the webhook fires the moment the bank confirms.

02 The API

An API that reads like the ledger it writes.

Resources map to accounting, not to our database. Accounts, transfers and entries are first-class, versioned, and typed in every SDK. What you send is what gets journaled.

  • Idempotent by default. Every write takes a key. Retries are safe, always.
  • Signed webhooks, ordered per account. Replay any window from the dashboard.
  • Dated API versions. Pin a version; we never change it underneath you.
  • Sandbox with fault injection. Fail a rail, delay a webhook, test your reconciliation.
Read the quickstart →
POST /v1/transfers 
curl https://api.ledgerline.dev/v1/transfers \
  -u $LEDGERLINE_KEY: \
  -H "Idempotency-Key: ord_8841" \
  -d source=acct_ops_eur \
  -d destination=acct_merchant_41 \
  -d amount=25000 \
  -d currency=eur
import Ledgerline from "@ledgerline/node";
const ll = new Ledgerline(process.env.LEDGERLINE_KEY);

const transfer = await ll.transfers.create({
  source: "acct_ops_eur",
  destination: "acct_merchant_41",
  amount: 25_000, // minor units
  currency: "eur",
}, { idempotencyKey: "ord_8841" });
import os, ledgerline

ll = ledgerline.Client(os.environ["LEDGERLINE_KEY"])

transfer = ll.transfers.create(
    source="acct_ops_eur",
    destination="acct_merchant_41",
    amount=25_000,  # minor units
    currency="eur",
    idempotency_key="ord_8841",
)
