Follow one payment

A payment is a story the ledger tells in order.

01 / 04

The request lands

Your server calls POST /v1/payments with an idempotency key. Retry it a hundred times and it still happens exactly once.

02 / 04

Funds are held, not moved

A hold reserves balance on the wallet the instant the intent is valid. Available drops; nothing is posted until you say so.

03 / 04

Entries post as a set

Debits and credits commit in one atomic write. If they do not sum to zero, the write is rejected before it exists.

04 / 04

Settled, signed, delivered

A signed webhook reaches your service in tens of milliseconds, and every balance projection already agrees with the books.

Our one opinion

Money should move like data does in a good system: in order, exactly once, and with a receipt nobody can quietly edit. Everything else we build is in service of that sentence.

The API

One call. Two sides. Always balanced.

A transfer is a set of entries. You describe the movement; Ledgerline validates, posts and publishes it atomically, then tells you what changed.

  • Idempotent by default

    Every write takes a key. Network retries are safe, duplicates are impossible.

  • Webhooks you can replay

    Signed, ordered, retried with backoff. Rewind any endpoint to any event.

  • A sandbox with time travel

    Fast-forward settlement windows and test month-end close in an afternoon.

curl https://api.ledgerline.dev/v1/transfers \
  -H "Authorization: Bearer $LL_SECRET_KEY" \
  -H "Idempotency-Key: ord_8841_capture" \
  --json '{
    "ledger": "led_marketplace",
    "amount": 12500,
    "currency": "USD",
    "debit": "acct_wallet_aria",
    "credit": "acct_payable_oak",
    "metadata": { "order": "8841" }
  }'
import Ledgerline from "@ledgerline/node";

const ll = new Ledgerline(process.env.LL_SECRET_KEY);

const txn = await ll.transfers.create({
  ledger: "led_marketplace",
  amount: 12500,
  currency: "USD",
  debit: "acct_wallet_aria",
  credit: "acct_payable_oak",
}, { idempotencyKey: "ord_8841_capture" });
