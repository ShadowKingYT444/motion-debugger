# Constrained transition authoring

The runtime schema is `transitionPlanSchema` exported by Motion Debugger. Serialize `schemaVersion: 1`, an explicit `browser-monotonic-ms` or `controlled-preview-ms` clock, stable logical actor IDs, DOM/SVG selectors or owned Three object/camera IDs, source locations and protected visual attributes. Projected screen positions use CSS pixels; orientation uses radians. World/parent positions use declared scene units and must be projected before pixel acceptance checks. Every beat has a trigger, purpose, from/to pose, acyclic `after` dependencies, duration and overlap. App states can still cycle open/close/reopen.

`inputPolicy` declares latest-input wins. Retargeting carries position and velocity. Direct scrub and intentional cuts carry none and exclude continuity checks. Acceptance includes useful completion, forbidden visible errors, reduced motion and per-actor destination tolerances, response/settling bounds and required travel. A stationary canvas is not actor evidence. Save permitted source files, protected files and bounded editable parameter names with the plan.

Use `createDOMBinding`, `createSVGBinding` or `createThreeBinding` on original objects. Resolve relative DOM positions with `begin()` at transition start. Invalidate on viewport/layout/scene changes and rebind before advancing. Three bindings own no renderer, camera or geometry; they write parent-local transforms in the existing render loop. Consumers explicitly project world destinations and supply custom material mappings when needed.

`createPersistentHandoff` retargets the existing spring channels without resets. `createStagedDecomposition` accepts editable beat targets and relative phase overlap. `createDragReleaseSettling` distinguishes direct pointer seeking from release retargeting. Advance controllers using native elapsed seconds from the consumer's existing renderer. Initialize the elapsed clock from the first native frame callback (zero initial delta); an earlier frame timestamp can precede performance.now() read during module setup. If the consumer stops its render loop while paused, reset that elapsed baseline when resuming so paused wall time is not integrated. All retain pause, replay and meaningful reduced-motion targets. Dispose controllers without disposing consumer objects.

Before normal coding edits, call `snapshotProtectedDesign(projectRoot, plan.edits.protectedFiles)` or freeze equivalent exact SHA-256 hashes. Verify these bytes after every candidate. Protect assets, layout, copy, materials and interactions unless explicitly permitted. Keep the current candidate, one minimal revision and optional alternative staging: at most three total under the same budget. Rendering, reviews, tool calls, decoding and failed attempts all count.

Execute the same short native journey and meaningful contracts for each candidate. Reject failed/unverified function or changed protected design first. Keep motion meaning, response, trackability and visual preference as separate judgments; cite actual delivered native capture/event/frame evidence. `selectMotionCandidate` validates bounds, measured costs and citation correspondence; it is a nomination guard, not an aesthetic oracle or proof that a model perceived the frames. Critic nominations may abstain and require calibration against blinded humans before serving as the main selector. Pose previews cannot support timing/performance claims.

Create a recoverable `createVerifiedMotionCheckpoint` only for a functional native-verified candidate with unchanged protected hashes. It retains exact authorized source bytes, plan/bindings, evidence IDs and hashes. Restore through normal host editing tools if later revisions fail. Retain every attempt and stop within the existing two-repair bound. Save successful app-specific configurations and regression journeys, with why they helped and which constraints passed.
